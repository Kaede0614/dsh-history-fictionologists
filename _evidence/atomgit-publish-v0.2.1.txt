# AtomGit 发版实跑记录（v0.2.1）

这份文件是 v0.2.1 发布前对**真实写入路径**的实跑记录。
上一版（0.2.0）在 CHANGELOG 里明写了一条技术债：「--publish 的真实写入路径没有实跑过」。
这里把它销掉。

- 平台：atomgit.com / api.atomgit.com/api/v5
- 仓库：Scombriformes/dsh-history-fictionologists
- 日期：2026-09-26
- 令牌权限（页面上的勾选）：用户「访问你的个人信息、最新动态等」=只读；
  项目「查看、创建、更新你的项目」=读写；项目「Repository: bash客户端的上下载」=读写；其余全部禁止。
- 命令里**没有** --allow-dirty：两次都是在干净工作区上跑的。

## 这两次实跑证明了什么

| 平台事实 | 本次实跑证据 |
|---|---|
| POST /orgs/:owner/repos 对个人空间可用 | -> 200，created repository Scombriformes/dsh-history-fictionologists |
| Release 已存在要 PATCH，且必须全量 body | PATCH .../releases/v0.2.1-rc.1 -> 200 |
| 附件走签名两步法（upload_url → PUT 带回 x-obs-*） | uploaded dsh-history-fictionologists-0.2.1.tgz，附件 id 218039 出现在 Release 上 |
| **同名附件覆盖不生效，必须先删再传** | DELETE .../attach_files/218037 -> 204 → 新附件 id=218039 |
| 「API 里有附件」≠「用户下到的就是构建的字节」 | download ... 125132 bytes, sha256 4f8ec752dca7f8bc… MATCHES the built tarball（两次都 MATCH） |
| 附件下载直链格式 /<owner>/<repo>/releases/download/<tag>/<file> | 两次回验用的都是这个 URL，均 200 |

**仍未验证**：GitHub 支路（scripts/release.mjs）的真实写入路径——本机没有 GitHub 令牌，
其写分支仍只有假 etch 的离线用例与逻辑推演。这条债**本版不还**，如实记着。
